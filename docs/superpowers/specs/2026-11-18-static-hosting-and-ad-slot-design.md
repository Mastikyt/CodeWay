# Публикация CodeWay и рекламный плейсхолдер — дизайн

## Цель и критерии успеха

Подготовить CodeWay к сдаче как цельный статический Vue-сайт с ясным рекламным местом и кратким сравнительным анализом четырёх бесплатных хостингов. Основной интерфейс остаётся на `/`; отдельная витрина Tailwind продолжает открываться через `/tailwind`. Деплой на Cloudflare Pages готовится так, чтобы после подключения репозитория можно было использовать `npm run build` и `dist`. Никакие URL публикации или успешный внешний деплой не заявляются до фактической проверки.

## Текущее состояние и ограничения

Проект содержит Vite multi-page build с двумя точками входа (`index.html`, `tailwind.html`), Vue-приложение CodeWay с Bootstrap и Tailwind, а также отдельную Tailwind-витрину. Основные страницы подключают API на `localhost:3001`; некоторые сервисы переходят на localStorage fallback. Это не полноценный production backend и не должно описываться как таковой. Папка пока не является Git-репозиторием, поэтому GitHub/Cloudflare Git-интеграция и внешний деплой требуют отдельной настройки/доступа.

## Предлагаемое решение

1. Добавить `AdSlot.vue` в общий слой `src/components` с вариантами `banner` и `sidebar`, доступной подписью «Рекламное место», пунктирной рамкой, светлой подложкой и адаптивным оформлением. Включить его на главную страницу основного приложения (`/`), чтобы блок был виден сразу при открытии опубликованного CodeWay без вытеснения ключевого контента.
2. Сохранить обе точки сборки. Настроить Vite public base для домена Pages (`/`) и правила Cloudflare Pages так, чтобы `/` отдавал основной `index.html`, `/tailwind` — витрину, а перезагрузка поддерживаемых SPA-маршрутов возвращала соответствующую HTML-точку входа. Проверить корректность абсолютных ссылок на assets после сборки.
3. Добавить сдаваемый Markdown-отчёт на русском: таблица Cloudflare Pages, GitHub Pages, Netlify и Vercel; для трафика, сборок, коммерции/рекламы, домена/SSL, Git, сценария и политики — краткие данные с датированными ссылками на первичные официальные документы, где доступны. Сомнительные/неофициальные заявления обозначить явно; указать, что тарифы и условия могут меняться. Дать рекомендацию Cloudflare Pages и GitHub Pages как осторожную альтернативу и объяснить 2–3 приоритета выбора. Объём целевого текста вне таблицы — 600–1000 слов, как требует задание.
4. Обновить README небольшим блоком о сборке/публикации и о пределах статического демо. Не включать секреты и не заявлять, что API доступен на опубликованном сайте.

## Проверка и сдаваемые материалы

- `npm run build` должен пройти и собрать обе точки входа.
- Запуск preview и проверка `/`, `/tailwind`, обновления маршрута витрины; проверить наличие и видимость AdSlot на странице.
- Снять локальный скриншот фактического плейсхолдера после запуска, если доступен браузерный инструмент.
- Деплой выполнять только после доступного репозитория и авторизации. Если их нет, оставить готовые пошаговые настройки Cloudflare Pages и честно указать, что живой URL ещё не создан.
- Предоставить фрагмент компонента, отчёт, локальный скриншот (если удалось снять), результат сборки и ссылку только если публикация действительно завершена.

## Вне объёма

Перенос backend/API, база данных в облаке, полноценная production авторизация, подключение рекламной сети, изменение содержимого тарифов хостингов без проверки источников, создание аккаунтов/репозитория от имени пользователя.
